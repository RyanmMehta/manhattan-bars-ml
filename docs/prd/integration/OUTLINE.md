## 8. Demo script (draft for `DEMO.md`, ~5 min, placeholder timings)

Before class: run `scripts/integration/warmup.sh` 10 min ahead; open frontend on phone + laptop (mirrored); clock chip shows **Sat 11:30 PM** (demo night).

1. **0:00 Problem (30 s)** — "Groups waste 30+ min (placeholder) deciding where to go; info is stale." One sentence on public data: 5,737 Manhattan venues, launch on 35 LES bars.
2. **0:30 Honesty line (15 s)** — point at the "demo data" badge: live reports are simulated until Scouts exist; `SYNTHETIC_DATA.md` lists how each piece gets replaced.
3. **0:45 Group flow (90 s)** — onboarding: hip-hop, want dancing, max cover $20, max line 15 min, group of 4, Ludlow St. → Tonight list: top pick shows match 91 / vibe 78 / confidence 0.71 (whatever data gives), reasons ("Hip-hop playing, 2 reports, 12 min ago"), a venue excluded for a 30-min line, a stale venue with low confidence. Explain three scores in one line each.
4. **2:15 Scout flow (60 s)** — open a venue → 10-second vibe check (crowd 5, dancing lots, line 5) → submit → state refreshes (n_reports +1, freshness 0 min) → leaderboard points.
5. **3:15 Operator flow (45 s)** — owner dashboard for one venue: post "$10 cover before midnight" offer → appears on the venue profile; demand chart (demo data).
6. **4:00 Later features (30 s)** — Run My Night (3 stops) / heatmap if flags on; else a screenshot slide.
7. **4:30 Under the hood (30 s)** — architecture diagram (specs): public data → reports → live state (decay, reputation) → recommend; complaint-risk model AUC ~0.72 shown only as "complaint risk". Tableau dashboard link.
8. **5:00 End** — repo + URL.

Fallbacks: (a) Render asleep → wait on warm-up, talk through step 1–2; (b) backend down → frontend `?mode=mock` (or local `make demo` on laptop); (c) everything down → 90-s screen recording in `docs/demo/` (recorded Nov 16).
