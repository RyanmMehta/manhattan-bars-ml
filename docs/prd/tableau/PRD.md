# PRD: tableau workstream (Nightlife Autopilot)

Status: planning (no code yet). Owner folder: `analytics/tableau/`. Branch: `nightlife/tableau`.

## 1. Problem
The course needs a Tableau dashboard deliverable (originally due **Oct 6**, now
overdue, so it should land as early as possible and no later than the Nov 17
integration). The project has a rich public-data venue database
(`data/manhattan_bars.db`: 5,737 venues, `v_bars` 1,727 bars) but nothing that
lets a grader, teammate or venue operator *see* it: where Manhattan's bars are,
how dense each neighbourhood is, how health grades and 311 noise complaints are
spread, and why the Lower East Side (zip 10002, 35 launch venues) is the launch
area. There is also no live nightlife data yet, so the "tonight" view must use
clearly-marked synthetic reports from the live-sim workstream.

Tableau is not always available (Tableau Public needs an account and a desktop
install; graders may not open a `.twbx`). So the dashboard also needs a static
Python-rendered stand-in PNG that shows the same sheets.

## 2. Goals
1. Reproducible CSV extracts from `manhattan_bars.db` that Tableau Public can load
   with no joins or cleaning in Tableau.
2. A published Tableau Public dashboard with 5 sheets (map, density, grades,
   LES zoom, synthetic tonight heatmap) and one combined dashboard view.
3. A Python stand-in image (`dashboard_standin.png`) showing the same 5 panels,
   regenerated by one command.
4. Step-by-step build instructions so anyone on the team can rebuild the
   workbook in about 30 minutes (placeholder estimate).
5. Every synthetic value is labelled "demo data" in Tableau and in the PNG.

## 3. Non-goals
- No live connection from Tableau to the backend or Postgres (CSV only).
- No new data collection or scraping; extracts read only from the existing DB
  and from live-sim outputs.
- No ML modelling. Complaint risk is shown as a public-data fact, never as a
  nightlife quality or vibe signal.
- No embedding the Tableau view inside the React frontend for the MVP (possible
  later item).
- Not editing `src/` or `data/manhattan_bars.db`.

## 5. User stories and acceptance criteria

**US-1 Extracts.** As a teammate, I run one command and get the CSVs Tableau needs.
- `python -I analytics/tableau/export_extracts.py` writes every file listed in
  OUTLINE §3 to `analytics/tableau/extracts/` in under 30 s.
- Row counts match the DB: `bars.csv` = 1,727 (or 1,709 with coordinates;
  the 18 rows without lat/lon are kept with a `has_coords=0` flag),
  `launch_venues.csv` = 35, `neighborhood_summary.csv` = one row per neighbourhood (15).
- Running twice gives byte-identical files (sorted rows, fixed float rounding).

**US-2 Manhattan map.** As a grader, I see every bar on a Manhattan map coloured
by noise complaints (or, in the tonight sheet, by synthetic vibe).
- Points sized/coloured by `noise_complaints` using a log-bucket scale
  (0, 1-2, 3-9, 10-49, 50+); tooltip shows name, address, venue_type, grade, complaints.
- Caption states "311 complaints = complaint risk, not nightlife quality".

**US-3 Density by neighbourhood.** As a pitch viewer, I can compare neighbourhoods.
- Horizontal bar chart of bar count per neighbourhood, sorted desc, with
  bars per 100 m density average as a second measure; LES/Chinatown highlighted.

**US-4 Health grades.** As an analyst, I see grade mix by neighbourhood.
- 100% stacked bar of `latest_grade` (A, B, C, N, Z, Not matched) per neighbourhood.
- "Not matched" (no DOHMH match) shown separately, not dropped.

**US-5 LES zoom.** As the team, I can show the 35 launch venues on their own.
- Map filtered to zip 10002 with launch venues marked and labelled; other 10002
  bars shown faded; a table of the 35 with type, grade, complaints.

**US-6 Synthetic tonight heatmap.** As a demo viewer, I see how busy LES venues
are by hour on a simulated night.
- Heatmap: rows = 35 launch venues, columns = hours 20:00-03:00, colour = mean
  synthetic `vibe_score` (0-100), with report count in tooltip.
- Title includes "DEMO DATA (synthetic)"; data comes only from files with
  `is_synthetic = 1`.
- If live-sim output is missing, the export script writes a clearly-marked
  placeholder (OUTLINE §5, SYN-T1) so the sheet still renders.

**US-7 Stand-in PNG.** As a grader without Tableau, I open one image.
- `python -I analytics/tableau/render_standin.py` writes
  `analytics/tableau/dashboard_standin.png` (≥ 2400×1600 px, 5 panels) from the
  same extracts. The synthetic panel has a visible "demo data" badge.

**US-8 Build instructions.** As a teammate, I can rebuild the workbook from scratch.
- `analytics/tableau/BUILD_TABLEAU.md` lists each step (connect, data types,
  geographic roles, each sheet's shelves, colours, dashboard layout, publish).
- A teammate who did not write it follows it and publishes (target ≤ 45 min).

## 7. Requirements
Functional
- F1 Extracts read only from `data/manhattan_bars.db` (read-only connection) and
  `data/synthetic_live/` (live-sim output).
- F2 Every extract has a header row, UTF-8, comma-separated, ISO dates, `.` decimal.
- F3 Every extract has `is_synthetic` (0 for public-data extracts, 1 for synthetic).
- F4 Synthetic extract files live under `analytics/tableau/extracts/synthetic/`
  and start with `syn_`.
- F5 `venue_id` column (= SLA `license_id`) in every venue-level extract so
  sheets can be joined/blended in Tableau.
- F6 Stand-in PNG and Tableau sheets use the same colour scales (defined once in
  `analytics/tableau/style.py` and documented in BUILD_TABLEAU.md).

Non-functional
- N1 Python 3.11+ with existing `requirements.txt` plus `matplotlib` only.
- N2 Extract + render together run in < 60 s on a laptop.
- N3 Deterministic output (fixed seed for any placeholder, sorted rows).
- N4 Total extracts < 5 MB (Tableau Public upload limit is far higher; keep repo light).

## 10. Risks
| Risk | Mitigation |
|---|---|
| Deadline already passed (Oct 6) | Ship public-data sheets first (no dependency), add tonight sheet after |
| live-sim output late or schema drift | SYN-T1 placeholder generator with the exact contract schema; validation in tests |
| Viewers read complaints as "best bars" | Caption on every complaint sheet; complaint scale in neutral grey/orange, not "hot" |
| Tableau Public geocoding fails on lat/lon | Explicit Latitude/Longitude geographic roles in instructions; drop 18 null-coord rows from maps only |
| Tableau Public makes data public | Only public data + synthetic; no user data ever exported |
| Neighbourhood labels are zip-based approximations | Note in captions; neighbourhood = `ZIP_TO_HOOD` mapping in `src/build_db.py` |
| Tableau unavailable for the grader | Stand-in PNG + PDF export of dashboard committed |
